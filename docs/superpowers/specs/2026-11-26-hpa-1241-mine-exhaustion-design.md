# HPA-1241 — Mine exhaustion, refill and parallel mining (design specification)

Linear: https://linear.app/cwchanap/issue/HPA-1241/mining-mines-run-dry-and-refill-and-rigs-work-several-mines-at-once  
Baseline: main at aee2a5acccdaa9bf6ebd9b87725182c82767073d (merged PR #57, HPA-1243).  
Status: proposed; implementation and acceptance evidence belong on this same draft PR.

## 1. Product contract and scope

Mine HP becomes real, persisted simulation state. Each placed rig works exactly one uniquely adjacent deposit. Multiple deposits at a site can produce simultaneously; an exhausted deposit and its rigs stop contributing production, but other deposits continue. All cargo remains in one site pool. A full pool stops both production and HP drain; refill timers still run, even without rigs. A dry deposit refills automatically after exactly two hours, including while away. Selling cargo does not heal HP. Moving/recalling/redeploying/upgrading rigs never resets HP or the ever-exhausted fact. A dry mine remains a legal deployment target if it has an available slot; its rig is idle until refill (no additional placement rule).

**Release boundary:** all ten deposits at each of the fifteen authored sites have null max HP in this PR. The finite-HP behavior is exercised with injected test content, not a player setting or a live economy change. No real HP curve, ore-size multiplier, progression gate, commissioning change, price change or pacing-band change here. HPA-1244 owns those decisions and depends on this PR; HPA-1240 owns drag/drop and move. Surveying, site/planet unlocks, deploy commissioning, mastery, relaunch, sell, existing storage capacity formula, 24-hour offline cap and existing costs remain. The current 8×22 field, ten deposits, four bands, rail/scroll, cavern art and dock stay. No new art or SFX, no separate mining screen, no save migration.

## 3. Content and save model

Use an immutable value (proposed name `MineProgress`) in `SiteProgress.mines`, indexed exactly like `content.site(id).deposits`. Use authored deposit order, not screen order, sorting, geometry hashes or persisted rig-to-mine pointers. Rigs keep their current cell/tier records. Add only one site field to the exact JSON shape:

```json
"mines": [
  {"remainingHp": null, "refillAtUtc": null, "everExhausted": false},
  {"remainingHp": 420.0, "refillAtUtc": null, "everExhausted": true},
  {"remainingHp": 0.0, "refillAtUtc": "2026-11-26T20:00:00.000Z", "everExhausted": true}
]
```

Example entries only; the actual list contains ten. Finite examples exist only in fixture content in this PR. Use double HP for fractional damage. **Null remaining HP means full or unlimited**, resolved against authored max HP in simulation and views: finite effective HP = remainingHp ?? maxHp; unlimited has no numeric effective HP. For finite mines a non-null remaining HP is a partially depleted or dry value; refill restores null, clears deadline and retains everExhausted. A finite authored max must be positive and finite. Zero HP requires a valid UTC deadline and everExhausted true; nonzero or null HP must have no deadline. Unlimited requires all-null HP/deadline and false everExhausted. No separate exhausted flag.

Keep exact keys/types and list length; reject negative/nonfinite HP, inconsistent deadline/history, and unlimited entries with finite state. Normalize positive HP above authored max by clamping to max, and canonicalize full finite HP to null (consistent with cargo normalization); valid kernel outputs are already canonical. A valid UTC deadline is structural only: do not reject it because it is at/before the saved anchor, already passed at load, or outside anchor + 2h. Resolve due deadlines in the next accrual before calculating rates; future deadlines wait as stored. The kernel itself always schedules exactly two hours after depletion. This avoids a rounding slip wiping an entire save. Old saves without mines remain invalid; no migration.

Keep `MiningSave.initial`'s signature and all initial/reset callers unchanged. Every site starts with the same immutable list of pristine entries (null HP, null deadline, false history). Give the in-memory SiteProgress constructor an optional mines argument defaulting to that list so unrelated fixtures remain simple; toJson and strict decoding still require the field explicitly. Size the list using one deposit count derived from the shared authored band geometry in mining_content.dart, not a second hand-written layout or new registry parameter. The registry and repository test that this count equals every site's actual deposit list length. Preserve list defensive copying, copyWith (including nullable field clearing), JSON/equality/hashCode and `_copySites`; never silently drop mine state on sales, unlock, recall or other copies. Locked sites and all sites on locked planets must remain pristine: extend the existing guards in `_decodeSites` and `_validateInvariants` in mining_save_repository.dart to reject any mine with non-null HP, non-null refill deadline or true everExhausted. Check locked-site pristineness before canonicalizing numeric full HP to null so normalization cannot conceal non-pristine input; retain the invariant check on decoded state for locked planets. Reuse a single pristine predicate for the two guards. Relaunch/recovered load use the same initial state. Reuse repository validation of rig placements with new cap, including formerly valid over-cap saves resetting. Root keys and save timestamp stay unchanged.

Content contract:
- `maxMineHp(siteId, depositIndex)` returns double? (production default null for all). Provide one narrowly scoped immutable finite-HP content injection at existing `stellarMining` factory for tests; no runtime flags or alternate registry state. HPA-1244 replaces the authored defaults there.
- `mineDrainPerSecond(tier, extraction)` = 10 × existing `rigRateMultiplier(tier)` × existing `extractionRateMultipliers[extraction]`. T1–T5 = 10, 15, 22.5, 32.5, 45 at Extraction 0; Extraction 5 doubles. No old tier-index visual damage formula.
- Refill duration constant 2h. Deposit capacity = width (1/2/3/4), defined on authored deposit definition (derived from size, no duplicate mapping). Keep site cap 4. Count all occupied slots even for dry mines; reject with a clear `mineAtCapacity` reason in `evaluateMiningPlacement` after the existing `surveyingLocked` check, used by controller, view highlights, journey and decoder. Slot UI reports this cap, not perimeter size; actual free cells still must pass all existing adjacency/bounds/Surveying rules. Existing geometric perimeter cache remains. No change to commission/gate rules.
- Each rig's ore contribution uses existing site base rate, tier and Extraction; group rigs by deposit using uniqueAdjacentDeposit. Keep current effectiveSiteRate arithmetic, called on working rig tiers in original placement order (not a sum of separately rounded mine rates), and current effectiveSiteCapacity over **all** deployed rigs. HPA-1244 can change contribution by mine size in this same derivation, not add another simulation. Do not change current rate/capacity values for any authored unlimited configuration.

## 4. Deterministic site accrual

In `MiningSimulation`, factor one pure site advance routine returning updated immutable SiteProgress, produced ore and first fill instant (if reached). Keep AccrualResult and the existing outer summary shape unchanged; no animation metadata in the kernel. No I/O or Flutter. The outer accrue loop preserves the existing per-resource/per-planet totals, elapsed/capped summary, full-site IDs and unlocked-planet iteration. For unlocked sites with zero rigs or full cargo, still process due refills. Do not confuse unstaffed refill-only sites with full storage: after applying the site result, skip produced/productionByPlanet map updates for sites with no deployed rigs, and add fullSites only when capacity > 0 and stored >= capacity. Preserve staffed-site summary semantics; refills themselves produce no ore. Locked sites remain untouched.

For a fixed technology/rig placement window, group once and derive each mine's ore rate and drain. Start at lastAccruedAtUtc; use elapsed in microseconds, not one-second ticks. Resolve deadlines <= cursor before calculating active rates. With free storage, a rig works iff its mine is unlimited or positive HP. Compute total rate by passing working rig tiers in original placement order to effectiveSiteRate (mathematically the sum of mine contributions, with the existing floating-point evaluation order); drain per finite mine is sum of its working rig damage. Choose the earliest of:
1. window end;
2. next outstanding refill deadline (regardless of work/storage);
3. next finite working mine reaching zero (remaining HP / drain);
4. remaining cargo / total working ore rate (if positive).

Advance all working mines and shared cargo for the same elapsed slice. Clamp cargo and HP only at their physical bounds; do not drain HP for the time after storage fills. At depletion set HP=0, everExhausted=true and refillAtUtc=event time + 2h. At refill clear deadline and store null HP (effective HP is exact authored max); all rigs resume automatically if there is storage space. Process all simultaneous events, including events exactly at end of window (no post-end production). Avoid zero-length loops: consume due boundaries first, use positive event durations; use consistent microsecond ceiling for timestamp conversion and a small documented floating-point tolerance, not per-tick HP/ore rounding. Test fractional damage, close/identical boundaries and split-window equivalence; compare long-vs-short deadline differences within ±1 ms, HP/cargo within a documented small tolerance and everExhausted exactly. Round-trip every representative kernel output (including boundary, capped and partitioned windows) through actual repository save/load at its anchor and require exact canonical state equality, without recovery. Distinguish cross-partition numeric tolerance from exact serialization equality. If no work or future event in the window, jump to end. Complexity is proportional to actual depletion/refill/fill boundaries, not seconds away. All-unlimited cases have one cargo-fill/end interval.

Offline: use the first min(rawElapsed,24h) from saved anchor, matching the existing capped amount contract. Refill timestamps are real UTC. For a longer absence, after that capped window, resolve any outstanding refill due by actual now without adding extra production or damage; advance lastAccruedAtUtc to actual now as today. A full store and a mine with no rig still refill. Nonpositive/backward elapsed leaves state unchanged. Equivalence within the stated tolerance to short refreshes applies within the same <=24h accrual window, not beyond the intentional cap. Refill itself does not change cargo, capacity or commissioning.

Actions accrue under previous placement/technology before applying changes (including sell, deploy, upgrade, recall, research); keep existing controller persistence/rollback sequencing. Foreground refresh remains memory-only; checkpoint/reload preserve state; no wall-clock writes from views. Relaunch still resets directly.

## 5. Rate and storage projection

`SiteMetrics.of` currently computes aggregate rate from all rigs and `timeToFull` is straight-line. Replace the rate input with working rigs and share the site simulation's assignment/activity derivation. Keep SiteMetrics an instantaneous snapshot with its existing `of(content, site, progress, technology)` inputs; add dry/idle counts but no clock or 24-hour simulation. MineSiteView and StellarMapView never need time-to-full; they receive updated rate through SiteMetrics without a projection or new signature argument. Capacity remains all rigs; a site with a dry mine is still commissioned/operational with rigs, even at zero current rate. Distinguish available production rate from actual cargo increment: full cargo retains nominal working-mine rate as today, but produces/drains nothing. Dry rig is IDLE due to HP only, not full storage. Update Mine Site, Site Deck, Stellar Map totals, full-cargo checks/notification and any direct aggregate-rate readers to avoid drift. Add dry-mine count and idle-rig count to site metrics; include dry mines that currently have no rigs.

Remove `SiteMetrics.timeToFull(double cargo)` and expose `MiningSimulation.projectTimeToFull` backed by the **same event advance routine**, with an immutable site snapshot and explicit state.lastAccruedAtUtc anchor, stopping at first fill. Only `SiteDeckView.from` (compute once per eligible card and store `final Duration? timeToFull` on `MiningSiteCardView`) and `nextStorageFull` call the projection. The latter retains earliest-site selection. MineSiteView.from can use its already available state.lastAccruedAtUtc to derive countdown display without invoking projection. No linear estimate using current rate, no mutation, no alert-side arithmetic. Return null if locked, no rigs/capacity, already full, or fill not reached in the next 24h under unchanged rigs/technology/no selling. A currently fully idle but refilling site can have a real future fill. Chosen scope clarification: the 24h offline horizon is also the shared projection horizon, so hide FULL IN and do not arm alerts beyond it rather than predict an unaccruable offline fill. This is a conservative display decision, not a promise that longer foreground play cannot fill storage. Retain earliest across unlocked planets and deterministic tie order. Reuse existing single pending alert, scheduling/cancel ownership, checkpoint anchor and resume cancellation; no dry-mine notification. Projection test must accrue the same snapshot to its returned instant and show actual fill (within numeric tolerance), and just before is not full; no projection if insufficient within cap.

## 7. Proposed decisions / handoff

The ordered list with null-means-full-or-unlimited HP, structural UTC deadline validation, microsecond event loop, bounded shared FULL IN projection and placement-on-dry rule are implementation/design decisions to review in this draft. The cap handling is deliberate: refill is wall-clock recovery but mining work beyond 24h is discarded. No legacy save support. No player-visible finite HP until HPA-1244. Exercise finite states via injected content in existing simulation/controller/repository and widget/golden tests. Use mandatory single-platform MCP browser E2E on the real production build for live changes (unlimited HP absent, cap, recall/redeploy, persistence and production); no new test web entrypoint, app clock controls or browser save seeding. Compare actual finite-state goldens to Linear E–H (Linux VM only for pixel baselines; normal widget assertions remain active on macOS and Chrome), and production MCP screenshots to the unchanged map/layout contract. HPA-1244 owns live finite-state browser E2E. HPA-1244 will use everExhausted for progression and the content hooks for final numbers, not add new state ownership. HPA-1240 will reuse placement legality and the same accrued state for move.

See companion implementation plan for test matrix, mockup parity and single-platform MCP E2E acceptance. No implementation or verification is claimed by this design-only commit.
