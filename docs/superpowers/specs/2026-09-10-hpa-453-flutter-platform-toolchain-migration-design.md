# HPA-453 Flutter Platform Toolchain Migration Design

## Goal

Intentionally adopt the Flutter-generated Android/iOS scaffold migration that was removed from HPA-451, and make every existing repository-managed Flutter pin agree with that migration.

This is a platform-maintenance PR only. It must not change Horologium gameplay, mining domain behavior, persistence, presentation, assets, or package dependencies.

## Context

HPA-451 temporarily contained commit `3855f0e3c75ec0626a1f38454910e7c0e545826d`, generated after a newer Flutter SDK migrated Android plus eight iOS project files. Review correctly removed it because that feature PR still validated on Flutter 3.32.5 and the platform baseline would otherwise depend on an unspecified local SDK.

As of 2026-09-10:

- `main` is still on the pre-migration platform scaffold;
- `.github/workflows/flutter_ci.yml` and `.github/workflows/flutter_tests.yml` pin Flutter `3.32.5`;
- `.cursor/install.sh` also pins `FLUTTER_VERSION="3.32.5"` and describes itself as installing the CI-pinned SDK for Cloud Agent environments;
- the target Flutter stable hotfix is `3.47.2`;
- Flutter 3.41+ uses the UIScene lifecycle by default and auto-migrates eligible stock AppDelegate apps when `flutter build ios`/`flutter run` executes;
- Horologium's `AppDelegate.swift` is still the stock registration shape and does not need a custom `SceneDelegate.swift`;
- the known migration raises the actual Xcode iOS deployment target from 12.0 to 13.0, adopts the current AppDelegate/scene lifecycle integration, adds generated Swift-package/CocoaPods Xcode wiring, and adds the Android migrator compatibility flags.

HPA-453 is the existing task for this work. It is deliberately separate from feature development.

## Decision

Cut the repository over in one jump from Flutter **3.32.5** to **3.47.2 stable**.

Use the reverted `3855f0e` diff as the semantic review oracle for expected platform changes, not as a cherry-pick and not as permission for arbitrary generated drift. Run the migration/build under Flutter 3.47.2 and compare the result with that known nine-file platform surface.

Update all three existing repository-managed Flutter pin locations in the same PR:

- `.github/workflows/flutter_ci.yml`;
- `.github/workflows/flutter_tests.yml`;
- `.cursor/install.sh`.

Do not introduce a fourth pin mechanism or a compatibility layer for Flutter 3.32.5.

## Allowed implementation surface

### Platform scaffold

Exactly these nine platform paths are the expected generated scaffold migration:

1. `android/gradle.properties`
   - add only the Flutter migrator compatibility flags `android.builtInKotlin=false` and `android.newDsl=false`;
2. `ios/Podfile`
   - update the Flutter-generated iOS baseline comment from 12.0 to 13.0;
3. `ios/Podfile.lock`
   - commit the CocoaPods lock generated by the migrated iOS project;
4. `ios/Runner.xcodeproj/project.pbxproj`
   - change all three project-level `IPHONEOS_DEPLOYMENT_TARGET = 12.0` settings to `13.0`;
   - adopt the generated CocoaPods framework references/build phases and `FlutterGeneratedPluginSwiftPackage` integration;
5. `ios/Runner.xcodeproj/xcshareddata/xcschemes/Runner.xcscheme`
   - adopt the generated scheme pre-action/build preparation changes;
6. `ios/Runner.xcworkspace/contents.xcworkspacedata`
   - wire the Pods project into the workspace;
7. `ios/Runner/AppDelegate.swift`
   - conform to `FlutterImplicitEngineDelegate` and register plugins through `FlutterImplicitEngineBridge.pluginRegistry`;
8. `ios/Runner/Info.plist`
   - add the generated `UIApplicationSceneManifest` using Flutter's default `FlutterSceneDelegate` while preserving existing Horologium orientation and frame-duration settings;
9. `ios/Flutter/AppFrameworkInfo.plist`
   - accept the oracle's generated shape: remove the old `MinimumOSVersion` key/value rather than hand-writing it to 13.0.

A custom `SceneDelegate.swift` is not part of this migration. If Flutter 3.47.2 requests one because it detects custom lifecycle behavior, stop and reassess rather than adding it automatically.

### Existing toolchain pins

These three existing pin surfaces move from 3.32.5 to 3.47.2:

- `.github/workflows/flutter_ci.yml`;
- `.github/workflows/flutter_tests.yml`;
- `.cursor/install.sh`.

Keep their current structure and responsibilities. Do not add FVM, mise, asdf, `.flutter-version`, a reusable workflow, or another installer abstraction.

### Conditional generated-metadata exceptions

The normal implementation diff should contain only the nine scaffold files, the three pin files, and the HPA-453 planning docs.

Two generated metadata files require explicit review if Flutter 3.47.2 touches them:

- `.metadata` may be accepted only when the diff is limited to Flutter-generated revision/channel/migration bookkeeping caused by the pinned migration. Do not hand-edit it and do not accept unrelated project capability/platform changes.
- `pubspec.lock` is **not** a toolchain-version stamp. Its `sdks:` block records the SDK compatibility constraints of the locked dependency graph. If `flutter pub get` changes only that block while every package name/version/source/hash remains identical, inspect the delta before accepting it and record why it is required. Any package-entry change is out of scope and must stop the ticket.

These are conditional exceptions, not blanket additions to the allowlist.

## iOS compile evidence

The migrated native iOS host must be compiled before merge. `flutter test` on the existing macOS matrix row is not sufficient because it does not prove `Runner.app`, AppDelegate, Pods, Xcode project, scene manifest, or Swift-package wiring compiles.

For this hobby-project migration, do **not** permanently increase every future macOS CI run solely to validate HPA-453. Instead, make a successful local macOS simulator build a required PR-visible merge artifact:

```sh
flutter --version
flutter build ios --simulator --debug
```

The implementation PR must record the exact Flutter version, command, exit success, and the terminal success line showing the simulator app was built. A soft statement such as "iOS tested locally" is not sufficient.

If local macOS compilation cannot be produced reliably, the fallback is to add `flutter build ios --simulator --debug` to the existing `macos-latest` / `platform: ios` matrix row. Do not create a new workflow or job.

## Explicit non-goals

Do not:

- change any file under `lib/`, `test/`, or `assets/`;
- change `pubspec.yaml`;
- change hosted package versions or hashes in `pubspec.lock`;
- upgrade `audioplayers`, `shared_preferences`, `flutter_lints`, Gradle, AGP, Kotlin, CocoaPods, or any other dependency as a separate modernization step;
- perform Flutter's built-in Kotlin/Gradle DSL migration; retain the two compatibility opt-out flags for this ticket;
- add FVM, mise, asdf, `.flutter-version`, or another version manager;
- refactor duplicated pins into a new reusable workflow/custom action;
- add a custom `SceneDelegate.swift` without a concrete migration requirement;
- regenerate skipped visual goldens;
- alter bundle identifiers, signing, provisioning, app capabilities, orientations, or Horologium-specific Xcode settings;
- preserve compatibility with Flutter 3.32.5 after the cutover.

## Migration workflow

1. Start from current `main` with a clean worktree.
2. Prove all three existing repository pins are still 3.32.5 and prove the real Xcode baseline has three `IPHONEOS_DEPLOYMENT_TARGET = 12.0` entries.
3. Select Flutter `3.47.2` stable and record `flutter --version`.
4. Run dependency resolution without deliberately upgrading dependencies; inspect any lockfile metadata-only delta rather than accepting it automatically.
5. Trigger the Android/iOS project migration through `flutter build apk --debug` and `flutter build ios --simulator --debug`.
6. Inspect `git status --short` and `git diff --name-only` before accepting generated changes.
7. Keep the nine expected scaffold paths; allow `.metadata` or `pubspec.lock` only under the conditional rules above. Any other generated Android/iOS/config drift stops the ticket.
8. Compare the nine-file semantic migration to `3855f0e`, including the three deployment-target changes and AppFrameworkInfo deletion semantics.
9. Update the three existing Flutter pins to 3.47.2.
10. Run the full repository gate and publish the required iOS simulator-build evidence on the PR.

Do not use `flutter create .` as a blanket regeneration command: it has a wider overwrite surface than this ticket requires.

## Risks and stop conditions

### UIScene lifecycle cutover

Flutter 3.41+ can auto-migrate this stock AppDelegate path. The expected output is the `FlutterImplicitEngineDelegate`/`FlutterSceneDelegate` shape already represented by `3855f0e`. A request for custom app-lifecycle code, a custom `SceneDelegate.swift`, or additional native source files is a stop/rescope signal.

### Android built-in Kotlin / new Gradle DSL

Flutter 3.44+ can expose the newer Android project model. HPA-453 intentionally keeps `android.builtInKotlin=false` and `android.newDsl=false`. Additional Gradle/AGP/Kotlin migration files are not "generated noise"; stop rather than accepting them.

### New analyzer diagnostics

The 3.32.5 -> 3.47.2 jump also changes the bundled Dart/analyzer. If `flutter analyze --fatal-infos` now requires edits under `lib/` or `test/`, do not silently fold those edits into HPA-453. Record the failure and rescope the incompatible code separately unless the fix is proven to be configuration-only and within this ticket's boundary.

### Generated lock/metadata drift

`.metadata` revision bookkeeping may legitimately move. `pubspec.lock` SDK constraints may also be rewritten by a newer pub implementation, but they are dependency-compatibility metadata rather than a toolchain pin. Accept either only after the narrow diff checks above; package resolution changes remain out of scope.

### Xcode/CocoaPods generated identifiers

Generated object IDs and checksums may differ from `3855f0e`; semantic roles must match. Do not hand-normalize generated IDs merely to reproduce the old commit byte-for-byte.

### Baseline assertions

Before migration:

```sh
grep -R "3\.32\.5" .github/workflows/flutter_ci.yml .github/workflows/flutter_tests.yml .cursor/install.sh
grep -c "IPHONEOS_DEPLOYMENT_TARGET = 12.0;" ios/Runner.xcodeproj/project.pbxproj
grep -n "MinimumOSVersion" ios/Flutter/AppFrameworkInfo.plist
grep -n "GeneratedPluginRegistrant.register(with: self)" ios/Runner/AppDelegate.swift
! grep -q "android.builtInKotlin" android/gradle.properties
! grep -q "UIApplicationSceneManifest" ios/Runner/Info.plist
```

Expected deployment-target count: `3`.

After migration:

```sh
! grep -R "3\.32\.5" .github/workflows/flutter_ci.yml .github/workflows/flutter_tests.yml .cursor/install.sh

```

Expected deployment-target count: `3`.

### Normal diff guard

The normal implementation diff is limited to:

```text
android/gradle.properties
ios/Flutter/AppFrameworkInfo.plist
ios/Podfile
ios/Podfile.lock
ios/Runner.xcodeproj/project.pbxproj
ios/Runner.xcodeproj/xcshareddata/xcschemes/Runner.xcscheme
ios/Runner.xcworkspace/contents.xcworkspacedata
ios/Runner/AppDelegate.swift
ios/Runner/Info.plist
.github/workflows/flutter_ci.yml
.github/workflows/flutter_tests.yml
.cursor/install.sh
```

Planning docs are expected in the same PR. `.metadata` and an SDK-constraint-only `pubspec.lock` change are conditional reviewed exceptions as defined above. Any other production/configuration file is a hard stop.

### Repository gate

Run under Flutter 3.47.2:

```sh
dart format --output=none --set-exit-if-changed .
flutter analyze --fatal-infos
flutter test
flutter test --coverage
flutter test --platform chrome
flutter build apk --debug
flutter build web
flutter build ios --simulator --debug
```

The iOS simulator build must execute on macOS after the migrated workspace/Pods state settles and its success evidence must be visible on the PR.

## Acceptance criteria

HPA-453 is complete when:

- GitHub Actions and Cloud Agent bootstrap all use Flutter 3.47.2 rather than 3.32.5;
- the known nine-file Android/iOS scaffold migration is intentionally present;
- all three Xcode project deployment targets are 13.0;
- `AppFrameworkInfo.plist` matches the generated oracle semantics and no longer carries the old `MinimumOSVersion` entry;
- iOS successfully compiles a simulator `Runner.app` under Flutter 3.47.2 and PR-visible evidence records that result;
- Android debug and web builds still succeed;
- the full existing test/analyze/format gates pass;
- no Dart gameplay, mining, save, UI, asset, hosted-package, Gradle/AGP/Kotlin modernization, custom SceneDelegate, or golden-regeneration work is bundled into the PR;
- no second toolchain-management abstraction is introduced.
