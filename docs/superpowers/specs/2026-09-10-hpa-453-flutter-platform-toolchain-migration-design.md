# HPA-453 Flutter Platform Toolchain Migration Design

## Goal

Intentionally adopt the Flutter-generated Android/iOS scaffold migration that was removed from HPA-451, and make the repository's CI toolchain match that migration.

This is a platform-maintenance PR only. It must not change Horologium gameplay, mining domain behavior, persistence, presentation, assets, or package dependencies.

## Context

HPA-451 temporarily contained commit `3855f0e3c75ec0626a1f38454910e7c0e545826d`, generated after a newer Flutter SDK migrated Android plus eight iOS project files. Review correctly removed it because that feature PR still validated on Flutter 3.32.5 and the platform baseline would otherwise depend on an unspecified local SDK.

As of 2026-09-10:

- `main` is still on the pre-migration platform scaffold;
- `.github/workflows/flutter_ci.yml` and `.github/workflows/flutter_tests.yml` both pin Flutter `3.32.5`;
- the current Flutter stable hotfix is `3.47.2`;
- the known migration raises the iOS deployment baseline to 13.0, adopts the current AppDelegate/scene lifecycle integration, adds generated Swift-package/CocoaPods Xcode wiring, and adds the Android migrator compatibility flags.

HPA-453 is the correct existing task for this work. It has no blockers and is deliberately separate from feature development.

## Decision

Pin Horologium's active CI workflows to **Flutter 3.47.2 stable** and adopt only the corresponding known platform scaffold migration.

Use the reverted `3855f0e` diff as the review oracle for expected platform changes, not as permission for arbitrary generated drift. Run the migration/build under Flutter 3.47.2 and compare the result with that known nine-file platform surface.

If Flutter 3.47.2 attempts to modify additional platform/configuration files beyond the allowed list below, stop and reassess HPA-453 before committing those extra changes. Do not silently turn this ticket into a general Flutter modernization project.

## Allowed implementation surface

### Platform scaffold

Exactly these nine platform paths are in scope:

1. `android/gradle.properties`
   - add the Flutter migrator compatibility flags `android.builtInKotlin=false` and `android.newDsl=false`;
2. `ios/Podfile`
   - raise the declared iOS baseline from 12.0 to 13.0;
3. `ios/Podfile.lock`
   - commit the CocoaPods lock generated by the migrated iOS project;
4. `ios/Runner.xcodeproj/project.pbxproj`
   - adopt the generated CocoaPods framework references/build phases and `FlutterGeneratedPluginSwiftPackage` integration;
5. `ios/Runner.xcodeproj/xcshareddata/xcschemes/Runner.xcscheme`
   - adopt the generated scheme pre-action/build preparation changes;
6. `ios/Runner.xcworkspace/contents.xcworkspacedata`
   - wire the Pods project into the workspace;
7. `ios/Runner/AppDelegate.swift`
   - move plugin registration to the current implicit-engine delegate/bridge path;
8. `ios/Runner/Info.plist`
   - add the generated scene manifest/lifecycle configuration while preserving existing Horologium orientation and frame-duration settings;
9. `ios/Flutter/AppFrameworkInfo.plist`
   - accept the current Flutter-generated minimum-OS metadata shape associated with the iOS 13 migration.

### Toolchain pin

Only these two CI paths may change outside the platform scaffold:

- `.github/workflows/flutter_ci.yml`
- `.github/workflows/flutter_tests.yml`

Replace every active Flutter `3.32.5` pin with `3.47.2`. Keep the existing workflow/job structure, action versions, cache behavior, coverage upload, test matrix, and build commands unchanged.

## Explicit non-goals

Do not:

- change any file under `lib/`, `test/`, or `assets/`;
- change `pubspec.yaml` or `pubspec.lock` intentionally;
- upgrade `audioplayers`, `shared_preferences`, `flutter_lints`, Gradle, AGP, Kotlin, CocoaPods, or any other dependency as a separate modernization step;
- add FVM, mise, asdf, a `.flutter-version` file, or another version manager;
- refactor the duplicated workflow version pins into a new reusable workflow or custom action;
- add permanent new CI jobs solely for this migration;
- alter bundle identifiers, signing, provisioning, app capabilities, orientations, or Horologium-specific Xcode settings;
- preserve compatibility with Flutter 3.32.5 after the cutover.

The repository has no production-user backward-compatibility requirement for this platform baseline. The target after merge is Flutter 3.47.2.

## Migration workflow

1. Start from current `main` with a clean worktree.
2. Select Flutter `3.47.2` stable and record `flutter --version` in verification notes.
3. Run dependency resolution without deliberately upgrading dependencies.
4. Trigger the Android/iOS project migration through the normal Flutter build/tooling path.
5. Inspect `git status --short` and `git diff --name-only` before accepting generated changes.
6. Keep only the nine allowed platform paths. Compare their semantic changes to `3855f0e`.
7. Update the two existing GitHub Actions Flutter pins to `3.47.2`.
8. Run focused platform builds, then the full repository gate.

Do not use `flutter create .` as a blanket regeneration command: it has a wider overwrite surface than this ticket requires.

## Validation

### Diff guard

Before test/build verification, the implementation diff must contain no production file outside:

```text
android/gradle.properties
ios/Flutter/AppFrameworkInfo.plist
ios/Podfile
ios/Podfile.lock
ios/Runner.xcodeproj/project.pbxproj
ios/Runner.xcodeproj/xcshareddata/xcschemes/Runner.xcscheme
ios/Runner.xcworkspace/contents.xcworkspacedata
ios/Runner/AppDelegate.swift
ios/Runner/Info.plist
.github/workflows/flutter_ci.yml
.github/workflows/flutter_tests.yml
```

Planning docs for HPA-453 are expected in the same PR and are exempt from this production-file guard.

### Repository gate

Run under Flutter 3.47.2:

```sh
dart format --output=none --set-exit-if-changed .
flutter analyze --fatal-infos
flutter test
flutter test --coverage
flutter test --platform chrome
flutter build apk --debug
flutter build web
flutter build ios --simulator --debug
```

The iOS simulator build must run on macOS with the migrated workspace/Pods state. A successful Dart/widget test run alone is not sufficient evidence for this ticket.

### CI expectation

After the two workflow pins move to 3.47.2, existing GitHub Actions jobs should pass without structural changes. If a workflow fails because 3.47.2 reveals an unrelated code/dependency incompatibility, fix only what is required to make the explicit toolchain cutover work; if that requires expanding into gameplay/domain/package-upgrade work, stop and rescope instead.

## Acceptance criteria

HPA-453 is complete when:

- CI and local verification use Flutter 3.47.2 rather than 3.32.5;
- the known nine-file Android/iOS scaffold migration is intentionally present on `main`;
- iOS builds successfully for the simulator with the new AppDelegate/scene/Xcode workspace wiring;
- Android debug and web builds still succeed;
- the full existing test/analyze/format gates pass;
- no Dart gameplay, mining, save, UI, asset, or package-dependency behavior changes are bundled into the PR;
- no second toolchain-management abstraction is introduced.
