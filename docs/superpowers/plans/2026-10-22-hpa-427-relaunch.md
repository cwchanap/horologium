## Task 1: Save counter and sale helper

### Production

- `lib/mining/mining_state.dart`: add `final int relaunchCount` to `MiningSave` with constructor, `initial({required nowUtc, int relaunchCount = 0})`, `copyWith`, `toJson` (`'relaunchCount'` last), `==`, and `hashCode`.
- `lib/mining/mining_save_repository.dart`: add `'relaunchCount'` to the exact root-key set and the error message; decode it as a non-negative `int` (reject doubles, strings, and negatives).
- `lib/mining/mining_content.dart`:
  - `static const relaunchSaleBonus = 0.5;`
  - `static double saleMultiplier(int relaunchCount)`;
  - `MiningPlanetId get finalPlanetId => MiningPlanetId.values.last;`
  - `double cargoValue(MiningSiteId site, double amount, int relaunchCount)`.
- Route every sale-value computation through `cargoValue`:
  - `mining_controller.dart` `sellAllCargo`;
  - `site_deck_view.dart` (two places);
  - `mine_site_view.dart` (two places);
  - `mining_progression_views.dart` (two places).
  Preserve rounding: `cargoValue` returns `double`; floor each single-site preview, but **sum unrounded values before a single `floor()`** in `sellAllCargo` and every planet-wide projection. After this, `rg -n "saleValuePerUnit" lib` lists only the content definitions and `cargoValue`.

### Tests

- `test/mining/mining_state_test.dart`: initial `relaunchCount` is 0; `copyWith`, `toJson`, and equality include it.
- `test/mining/mining_save_repository_test.dart`: add `relaunchCount` to every current-shape fixture; a save with 3 round-trips; missing key, `-1`, `1.5`, and `"1"` each clean-reset with `recoveredFromInvalidSave`.
- `test/mining/mining_content_test.dart`: multipliers 1.0 / 1.5 / 2.0; `finalPlanetId == MiningPlanetId.ceresFrontier`; `cargoValue` for one site at 0 and 2 relaunches.
- `test/mining/mining_controller_test.dart`: a state with `relaunchCount: 1` sells for ×1.5 (floored as today).
- `test/mining/site_deck_view_test.dart`, `mine_site_view_test.dart`, `mining_progression_views_test.dart`: one relaunched-state case each where the **active-planet aggregate** projected value equals the controller's sale revenue. Use fractional amounts on two sites to catch premature per-site flooring; single-site cards still floor individually.

## Task 2: The relaunch action

### Production

- `MiningController.relaunch()` inside `_enqueueMutation`: accrue; if `!content.isPlanetMastered(content.finalPlanetId, _commissionedSiteIds(candidate.state))` return `MiningActionResult.failure('Master ${content.planet(content.finalPlanetId).name} first.')`; else build `MiningSave.initial(nowUtc: now, relaunchCount: candidate.state.relaunchCount + 1)`, save, assign, and return success with `Relaunch $n — sales ×${multiplier.toStringAsFixed(1)}.`.
- `lib/mining/next_goal_view.dart`: rename `MiningGoalKind.frontiersMastered` to `relaunch`; `complete()` returns title `Relaunch`, detail `Start again with sales ×<next>.`, target `MiningGoalTarget.stellarMap()`. Delete the "Keep upgrading" branch.
- `StellarMapView`: add `relaunchCount`, `isRelaunchUnlocked` (last authored planet mastered), `canRelaunch` (`isRelaunchUnlocked && !isBusy`), and `nextSaleMultiplier`. These are derived read-model values, not saved flags.

### Tests

- Controller: fails before Ceres mastery with no repository write (use the existing counting repository fake); succeeds after mastery and equals `MiningSave.initial(nowUtc: clock(), relaunchCount: 1)`; a second relaunch after re-mastery gives 2; the Ceres reward is granted again in run 2.
- `next_goal_view_test.dart`: the post-Ceres step is `relaunch` with `×1.5` at count 0 and `×2.0` at count 1; replace the old `frontiersMastered` expectations, including the tracks-left case.
- `mining_progression_views_test.dart`: `isRelaunchUnlocked` false with the final planet short one site, true when mastered, and stays true while busy; `canRelaunch` false while busy. Pin the current final planet (Ceres) in content tests but make production depend on `MiningPlanetId.values.last`.

## Task 3: Stellar Map card, sheet, and shell

### Production

- `lib/mining/presentation/relaunch_sheet.dart`: a `MiningSheetFrame` titled `Relaunch` listing what resets and what stays, the next multiplier, and Cancel / Relaunch buttons (`Key('relaunch-cancel')`, `Key('relaunch-confirm')`).
- `lib/mining/presentation/stellar_map_screen.dart`:
  - a `_RelaunchCard` after the planet cards when `view.isRelaunchUnlocked`, with `Key('stellar-map-relaunch')`; disable its button when `!view.canRelaunch` rather than hiding the card during persistence;
  - a header line `RELAUNCH <n> · SALES ×<m>` when `relaunchCount > 0`; keep adequate spacing between the extra header line and the scrolling planet cards on narrow portrait screens;
  - a new `VoidCallback onRelaunch` parameter.
- `lib/mining/presentation/mining_shell.dart`: `onRelaunch` plays `tap` and opens the sheet; confirm calls `_controller.relaunch()`; on success play `milestone`, show the message, pop to the Site Deck, and publish the new state; on failure play `reject` and show the message (the same shape as the existing planet-unlock handler).

### Tests

- `test/mining/presentation/stellar_map_screen_test.dart`: no card before mastery; card after; keep card visible but its action disabled while busy; after a relaunch the header line appears; no overlap/overflow at 360×640 and 430×932 with the real Orbitron font loaded as in `visual_parity_golden_test`.
- `test/mining/presentation/relaunch_sheet_test.dart`: copy, both buttons, no overflow at both sizes.
- `test/mining/presentation/mining_shell_test.dart`: from a final-planet-mastered save, Stellar Map → Relaunch → Cancel leaves state unchanged; Relaunch → confirm saves once, plays `milestone` only after successful persistence, shows the Homeworld Site Deck with 100 cash, and a reload keeps `relaunchCount` 1. A second rapid confirm must not queue another relaunch.

  - Economy and progression: "Mastering the final authored planet unlocks Relaunch; each relaunch adds +50% sale value through `MiningContentRegistry.cargoValue`, the only sale-value path."
