## Task 1: Save counter and sale helper

### Production

- `lib/mining/mining_state.dart`: add `final int relaunchCount` to `MiningSave` with constructor, `initial({required nowUtc, int relaunchCount = 0})`, `copyWith`, `toJson` (`'relaunchCount'` last), `==`, and `hashCode`. Add `int saleValue(MiningContentRegistry content, MiningPlanetId planet)` here too: use this save's `sites` and `relaunchCount`, sum unrounded `content.cargoValue` for that planet's authored sites, then floor once. `MiningSave` already imports `mining_content.dart`; no new dependency or state owner.
- `lib/mining/mining_save_repository.dart`: add `'relaunchCount'` to the exact root-key set and the error message; decode it as a non-negative `int` (reject doubles, strings, and negatives).
- `lib/mining/mining_content.dart`:
  - `static const relaunchSaleBonus = 0.5;`
  - `static double saleMultiplier(int relaunchCount)`;
  - `MiningPlanetId get finalPlanetId => MiningPlanetId.values.last;`
  - `double cargoValue(MiningSiteId site, double amount, int relaunchCount)`;
  - `formatSaleMultiplier(double multiplier)` beside `formatMiningCash` / `formatMiningUnits`; format up to two decimal digits, trimming trailing zeros, so a tuned ×1.75 stays ×1.75 rather than ×1.8. Call sites pass `MiningContentRegistry.saleMultiplier(n)`; use it for controller messages, next goal, Stellar Map card, sheet, and status line.
- Route the seven current raw sale-value expressions through the existing owners:
  - `mining_controller.dart` `sellAllCargo`: use `candidate.state.saleValue(content, activePlanetId)` for revenue, while its existing loop still handles sold quantities and resets cargo; do not compute another gross total.
  - `site_deck_view.dart`, `mine_site_view.dart`, `mining_progression_views.dart`: single-site previews use `content.cargoValue(id, amount, state.relaunchCount).floor()`, while each **planet-wide** total uses `state.saleValue(content, planetId)`. Remove repeated accumulation of gross value, but keep existing cargo/rate/capacity loops.
  - Aggregate rounding lives in `MiningSave.saleValue`: sum unrounded site values, floor **once**. The floored aggregate may differ from summing floored site cards, as it already does today. After this, `rg -n "saleValuePerUnit" lib` should list only content definitions and `cargoValue`.

### Tests

- `test/mining/mining_state_test.dart`: initial `relaunchCount` is 0; `copyWith`, `toJson`, and equality include it; a two-site fractional-cargo fixture verifies `saleValue` sums unrounded amounts then floors once.
- `test/mining/mining_save_repository_test.dart`: add `relaunchCount` to every current-shape fixture; a save with 3 round-trips; missing key, `-1`, `1.5`, and `"1"` each clean-reset with `recoveredFromInvalidSave`.
- `test/mining/mining_content_test.dart`: multipliers 1.0 / 1.5 / 2.0; `finalPlanetId == MiningPlanetId.ceresFrontier`; `cargoValue` for one site at 0 and 2 relaunches; `formatSaleMultiplier` outputs ×1.5, ×1.75, and ×2 (or equivalent without duplicating the prefix).
- `test/mining/mining_controller_test.dart`: with `relaunchCount: 1` and two fractional-cargo sites, controller revenue equals **pre-sale** `state.saleValue(content, activePlanetId)`. Reuse existing Site Deck, Mine Site, and Stellar Map view tests for display contracts; don't add three redundant per-view fractional-rounding tests.

## Task 2: The relaunch action

### Production

- `MiningController.relaunch()` inside `_enqueueMutation`: no accrual (the reset discards accrued cargo and mastery only reads commissioned flags); if `!content.isPlanetMastered(content.finalPlanetId, _commissionedSiteIds(_state))` return `MiningActionResult.failure('Master ${content.planet(content.finalPlanetId).name} first.')`; else build `MiningSave.initial(nowUtc: now, relaunchCount: _state.relaunchCount + 1)`, save, assign, and return success with `Relaunch $n — sales ×${formatSaleMultiplier(MiningContentRegistry.saleMultiplier(n))}.` (avoid per-surface `toStringAsFixed(1)`).
- `lib/mining/next_goal_view.dart`: rename `MiningGoalKind.frontiersMastered` to `relaunch`; `complete()` returns title `Relaunch`, detail `Start again with sales ×<next>.`, target `MiningGoalTarget.stellarMap()`. Delete the "Keep upgrading" branch.
- `StellarMapView`: add `relaunchCount`, `isRelaunchUnlocked` (last authored planet mastered), `canRelaunch` (`isRelaunchUnlocked && !isBusy`), and `nextSaleMultiplier`. These are derived read-model values, not saved flags.

### Tests

- Controller: fails before final-planet mastery with no repository write (use the existing counting repository fake); succeeds after mastery and equals `MiningSave.initial(nowUtc: clock(), relaunchCount: 1)`. Call `relaunch()` **twice without awaiting either**: one success, one mastery-gated failure, `relaunchCount == 1`, and one save. A second successful relaunch after re-mastery gives 2; the final-planet reward is granted again in run 2.
- `next_goal_view_test.dart`: the post-Ceres step is `relaunch` with `×1.5` at count 0 and `×2.0` at count 1; replace the old `frontiersMastered` expectations, including the tracks-left case.
- `mining_progression_views_test.dart`: `isRelaunchUnlocked` false with the final planet short one site, true when mastered, and stays true while busy; `canRelaunch` false while busy. Pin the current final planet (Ceres) in content tests but make production depend on `MiningPlanetId.values.last`.
- `test/integration/merge_mining_journey_test.dart`: **in this task**, replace the stale `MiningGoalKind.frontiersMastered` expectation and title at the first final mastery with `MiningGoalKind.relaunch` / `Relaunch`; don't leave the whole tree failing to compile until Task 4.

## Task 3: Stellar Map card, sheet, and shell

### Production

- `lib/mining/presentation/relaunch_sheet.dart`: a `MiningSheetFrame` titled `Relaunch` listing what resets and what stays, the next multiplier, and Cancel / Relaunch buttons (`Key('relaunch-cancel')`, `Key('relaunch-confirm')`).
- `lib/mining/presentation/stellar_map_screen.dart`:
  - a `_RelaunchCard` after the planet cards when `view.isRelaunchUnlocked`, with `Key('stellar-map-relaunch')`; disable its button when `!view.canRelaunch` rather than hiding the card during persistence;
  - a status line `RELAUNCH <n> · SALES ×<m>` when `relaunchCount > 0` as the **first child** of the existing `stellar-map-scroll` Column, with ordinary spacing; leave the absolutely positioned `_MapHeader` and scroll bounds untouched;
  - a new `VoidCallback onRelaunch` parameter.
- `lib/mining/presentation/mining_shell.dart`: `onRelaunch` opens the existing `_showMiningSheet` with a `MiningSheetFrame` confirmation; cancel just dismisses it. On confirm dismiss the sheet, snapshot `relaunchCount`, await `_runSheetAction(() => _controller.relaunch(), sound: GameSound.milestone, successMessage: ...)`, then compare the counter. Only if it increased, call `_showPrimarySurface(MiningNavigationDestination.siteDeck)`. `_runSheetAction.onSuccess` is Mine-Site-local and cannot navigate from Stellar Map; the explicit navigation tap is lower priority than the milestone sound. Existing action wiring owns rejection, refresh and snackbar; no second mutation handler.

### Tests

- `test/mining/presentation/stellar_map_screen_test.dart`: no card before mastery; card after; keep card visible but its action disabled while busy; after a relaunch the status line is findable **inside** `stellar-map-scroll`. Use the existing screen tests for responsive layout; skip a new font-loaded absolute-header overlap test, because no header offsets change.
- `test/mining/presentation/relaunch_sheet_test.dart`: copy, both buttons, no overflow at both sizes.
- `test/mining/presentation/mining_shell_test.dart`: from a final-planet-mastered save, Stellar Map → Relaunch → Cancel leaves state unchanged; Relaunch → confirm saves once, plays `milestone` only after successful persistence, shows the Homeworld Site Deck with 100 cash, and a reload keeps `relaunchCount` 1. The deterministic double-relaunch assertion belongs in Task 2's controller test, not a widget tap race.

## Task 4: Journey

- `test/integration/merge_mining_journey_test.dart`:
  - Extract only the reusable public-action sequence from fresh Homeworld through final-planet mastery into `_playRun(JourneyPlayer player, …)`; return `({Duration opening, Duration mars, Duration last})` measured from the **individual run start**. Refactor the existing local helpers to refer to the passed player's controller; do not create a second journey harness.
  - Keep every current opening/Mars/Ceres **absolute min and max assertion on run 1 only**, outside the common helper. Preserve the existing `OPENING`, `CADENCE`, `MASTERY`, and `RELOAD` diagnostics and one-time reward/recall/redeploy checks.
  - Run 1 still verifies save reload **and the 30-hour absence / 24-hour accrual cap** before relaunch. This must precede the reset: offline production summary requires the mastered state. After that assertion, call `returned.relaunch()` on the **returned controller**, not on `controller` or `reloaded`, whose state no longer matches persisted state.
  - Construct `JourneyPlayer(returned, clock, content)` for run 2. Assert fresh Homeworld (100 cash, zero tech, relaunchCount 1) and play the same action sequence. Assert only relative run-2 times: `run2.last <= run1.last * 0.8` at 2-hour cadence and `run2.last < run1.last` at 6-hour cadence; do not apply run-1 absolute pacing minimums. Measure from the start of each run, excluding the 30-hour absence between runs.
  - Update `JourneyPlayer._siteIncome` to use `content.cargoValue(id, units, state.relaunchCount)` instead of raw `saleValuePerUnit`, so reinvestment diagnostics reflect the current bonus. This remains test-only and is not an economy change. `rg -n "saleValuePerUnit" lib test/integration/merge_mining_journey_test.dart` should then find raw multiplications only inside `cargoValue` and authored definitions.
  - Log `RELAUNCH run=2 mastery=<h> run1=<h> finalPlanet=<name>`; reload and expect `relaunchCount == 1`.
- If the 20% check fails, tune only `relaunchSaleBonus` and re-run. Record the final value and both cadences' run times in the PR. Do not invent a run-2 minimum or over-acceleration threshold without player evidence.
